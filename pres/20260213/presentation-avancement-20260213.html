Optimisation React Query

Avant
const [levels, setLevels] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

useEffect(() => {
  fetchLevels()
    .then(setLevels)
    .catch(setError)
    .finally(() => setLoading(false));
}, []);
  • Appels dupliques dans chaque ecran
  • Pas de cache : rechargement a chaque navigation
  • Gestion manuelle du loading et des erreurs
Apres
const { data: levels,
  isLoading,
  error
} = useQuery({
  queryKey: ['levels'],
  queryFn: () => trpc.level.getAll.query(),
  staleTime: 5 * 60 * 1000,
});
  • Donnees partagees entre tous les ecrans
  • Cache automatique avec invalidation ciblee
  • Retry, loading et erreurs geres nativement

Cache intelligent

Les donnees sont mises en cache cote client et reutilisees sans rappeler l'API inutilement

Invalidation ciblee

Seules les donnees impactees par une action sont rafraichies, pas l'ensemble de l'application

Moins de calls API

Reduction significative du nombre de requetes vers le serveur pour une experience plus fluide

Gestion du reseau

Retry automatique en cas d'echec et gestion des etats de chargement normalises

Code simplifie

Remplacement des useEffect et useState manuels par des hooks declaratifs (useQuery, useMutation)

UX reactive

L'interface repond instantanement aux actions grace aux mises a jour optimistes du cache

Gestion des frais

Assurance Vie

Simulation realiste des frais appliques aux contrats d'assurance vie

  • Frais d'entree sur versement
  • Frais de gestion annuels
  • Frais de sortie (rachat)

PEA

Integration des frais lies au Plan d'Epargne en Actions

  • Frais d'entree (courtage achat)
  • Frais de gestion (droits de garde)
  • Frais de sortie (courtage vente)

CTO

Frais du Compte-Titres Ordinaire pour une simulation complete

  • Frais d'entree (commission achat)
  • Frais de gestion (tenue de compte)
  • Frais de sortie (commission vente)

Objectif pedagogique & realisme

Permettre aux utilisateurs de comprendre l'impact des frais sur leurs investissements a long terme, tout en rendant la simulation plus realiste. Les frais sont appliques automatiquement pour reproduire les conditions reelles du marche et offrir une experience educative fidele.

Amelioration de la fin de partie

Calcul endGame

A la fin de la partie, le score financier est calcule en additionnant : solde du wallet + valeur des assets + interets accumules

Validation des objectifs

Chaque objectif est valide via son goalType et goalValue. La partie est reussie si l'objectif principal (mandatory) est atteint

Modale de fin

Affichage d'une modale adaptee selon le resultat :
• Principal + bonus OK
• Principal OK / bonus KO
• Principal KO

Systeme de score

Score de 1 a 3 etoiles base sur 3 criteres :
• Objectifs principaux atteints
• Objectifs bonus atteints
• Quiz reussi

Meilleur score conserve

Le meilleur score obtenu est conserve par joueur et par niveau, permettant aux utilisateurs de suivre leur progression et de retenter les niveaux pour ameliorer leurs etoiles.
